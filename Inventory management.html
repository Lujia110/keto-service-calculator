⇅ 风险置顶
蓝底 = 自动计算联动（默认不可改） 黄底 = 已手动覆盖的值（可点↺还原） 白底 = 每天可手动调整 危险 注意 正常 数据保存在本机浏览器（localStorage），刷新不丢
一行 = 一个SKU ｜ 每日维护：账面、待报废、在途、C端实际/预测、安全库存
概念口径：当前账面库存 = 仓库系统里记录的数量（含待报废的）；良品库存 = 账面 − 待报废/异常 = 真正可发货的数量。
核心公式：良品 = 账面 − 待报废 ｜ C端可上架 = 良品 − OEM已锁定 − 安全库存 ｜ 覆盖周数 = 可上架 ÷ 周均消耗（取实际与预测的较大值，即保守估计）
OEM高概率折算比例（计入主表「OEM高概率」列）： 意向 0%（刚沟通、询价，不影响库存）｜ 高概率 50%（产品/价格/数量基本确认，有明确采购计划）｜ 高概率+明确时间 75%（已确认预计下单/交货时间，内部流程启动，70%~80%取中）｜ 已确认订单 100%（合同/PO/定金确认，必须锁库存）｜ 已下单 100%（正式订单，实际占用库存）。
⚠️ 高概率只做预警不锁库存（按比例折算计入「OEM高概率」列）；「OEM已锁定」仅统计已确认订单+已下单（100%）。折算比例在代码顶部 OEM_STATUS 可调整。
一行 = 一个 客户×SKU ｜ 状态/日期留空 = 跟随上方客户默认 ｜ 蓝底列随主表/状态自动联动
交付规则（库存决定交期）：
① 可分配 ≥ 需求 → 现货/短期交付，给正常交期；
② 部分有货 → 按「库存可满足」先排一批，缺口部分按采购周期另确认，可分批交付；
③ 完全缺货 → 才告知：该SKU需美国采购，标准采购周期约 8–10周，以订单确认及排期为准。
状态 → 库存计算比例：意向 0% ｜ 高概率 50% ｜ 高概率+明确时间 75% ｜ 已确认订单/已下单 100%
缺口按折算比例计算：高概率订单只预警，不直接触发采购；已确认/已下单订单有缺口才标 🔴 交付风险。
状态怎么填：大多数订单状态是按客户整体的（如客户A确认要下全部27个SKU）→ 在上方「客户订单状态」设一次即可，该客户所有行默认「跟随客户」自动生效；
个别产品状态不同 → 在那一行单独下拉选择即可覆盖。
一行 = 一个SKU本周 ｜ 填SKU自动带出产品名称+本周预测，日期自动算周次；每天/每周更新「本周实际」
字段口径：「本周预测」= 主表「未来10周C端预测」÷ 10（周均，自动带出可改）；「本周实际」= 本周至今实际消耗（每天更新累计值）；偏差 = 实际 − 预测。
「同步最近10周实际 → 主表」会把每个SKU最近10条记录的「本周实际」求和写入主表「过去10周C端实际」，并更新「本周C端实际」。
报废/异常单独留痕，避免「库存怎么少了300」说不清
报废是否计入总库存？是。报废通过「待报废/异常」直接从主表账面库存中扣除（良品 = 账面 − 待报废），无论来源是 OEM 客户还是 C 端，统一扣。
报废来源：OEM客户报废 / C端报废 / 其他，逐条记录来源，方便复盘是渠道原因还是产品质量原因。
流程：先记录（状态=待确认）→ 确认后点「⇄ 已确认报废 → 计入主表待报废」，自动累加到主表待报废字段并标记已扣库存。
